BEFORE M1 CAN START — MANUAL CHECKLIST
=======================================
Repo: MerverliPy/opencode-pilot
Date: 2026-05-12

Do these steps in order. Step 3 must be done before any PR is opened.



================================================================
STEP 1 — SET GITHUB_TOKEN PERMISSIONS (do this first)
================================================================
WHY FIRST: If this is not set before the first PR is opened,
the coverage comment in ci.yml and the back-commit in release.yml
will fail with a 403 permission error.

Go to:
  https://github.com/MerverliPy/opencode-pilot/settings/actions

Scroll to the bottom of the page to the "Workflow permissions"
section. Select:

  (o) Read and write permissions       ← change from default if needed
  [x] Allow GitHub Actions to create and approve pull requests

Click "Save".

What this enables:
  - ci.yml posts/updates the test coverage comment on pull requests
  - release.yml pushes the back-commit  "chore(release): vX.Y.Z [skip ci]"
  - release.yml creates GitHub Releases and publishes to GitHub Packages


================================================================
STEP 2 — TRIGGER THE FIRST CI RUN
================================================================
WHY: GitHub branch protection requires a status check to have run
at least once before it appears in the search box. "CI pass" will
not be searchable until the workflow has executed.

How to trigger it:
  a. Create any branch locally:
       git checkout -b ci/bootstrap
  b. Make a trivial change (e.g. add a blank line to BEFORE_M1.txt):
       echo "" >> BEFORE_M1.txt
  c. Commit it (must follow conventional commits format):
       git add BEFORE_M1.txt
       git commit -m "chore: trigger first CI run"
  d. Push and open a pull request against main:
       git push -u origin ci/bootstrap
       gh pr create --title "chore: trigger first CI run" --body "" --base main
  e. Wait for all five CI jobs to complete:
       commitlint, typecheck, lint, test, CI pass
  f. Once "CI pass" shows green, proceed to Step 3.
  g. You can close and delete this PR without merging it.

Note: You can leave this PR open during Step 3 if you prefer to
set branch protection immediately after CI passes.


================================================================
STEP 3 — CONFIGURE BRANCH PROTECTION
================================================================
Go to:
  https://github.com/MerverliPy/opencode-pilot/settings/branches

Click "Add branch protection rule"
(or click "Edit" if a rule for "main" already exists).

Fill in the form:

  Branch name pattern:   main

  Protect matching branches:
    [x] Require a pull request before merging
          Require approvals: 1
            (set to 0 if you are working solo and never want to be blocked)
          [x] Dismiss stale pull request approvals when new commits are pushed

    [x] Require status checks to pass before merging
          [x] Require branches to be up to date before merging

          In the search box labelled "Search for status checks":
            Type "CI pass" and select it from the dropdown.

          If "CI pass" does not appear in the search:
            - CI has not run yet. Go back and complete Step 2 first.
            - If it still does not appear, type "CI pass" exactly and
              press Enter to add it as a typed value.

    [x] Require conversation resolution before merging

    [x] Do not allow bypassing the above settings

Click "Save changes".

What "CI pass" covers:
  It is the aggregate gate job in .github/workflows/ci.yml.
  It only succeeds when ALL four of these jobs pass:
    - commitlint   (commit message format)
    - typecheck    (tsc --noEmit)
    - lint         (eslint, 0 warnings)
    - test         (jest, 80%+ coverage on all metrics)
  This is the only status check you need to require.


================================================================
STEP 4 — ADD OPENCODE_URL SECRET (optional)
================================================================
This is only needed to run the Benchmark workflow
(.github/workflows/benchmark.yml). Skip if you do not plan to
run benchmarks from CI. CI itself does not require this secret.

Go to:
  https://github.com/MerverliPy/opencode-pilot/settings/secrets/actions

Click "New repository secret" and enter:

  Name:   OPENCODE_URL
  Value:  http://your-opencode-server:port
          Examples:
            http://localhost:3000
            https://your-subdomain.trycloudflare.com

Click "Add secret".

To run the benchmark workflow after adding the secret:
  Go to: https://github.com/MerverliPy/opencode-pilot/actions
  Click "Benchmark" in the left sidebar.
  Click "Run workflow" → choose a suite → "Run workflow".


================================================================
STEP 5 — SET PACKAGE VISIBILITY (deferred — after first release)
================================================================
After the first successful push to main triggers release.yml and
publishes @MerverliPy/pilot to GitHub Packages, the package will
likely default to "private". Do this once after that happens.

If MerverliPy is a PERSONAL account:
  Go to: https://github.com/MerverliPy?tab=packages
  Click "pilot" → Package Settings (right side) →
  "Change package visibility" → Public → type "pilot" to confirm.

If MerverliPy is an ORGANIZATION:
  Go to: https://github.com/orgs/MerverliPy/packages
  Click "pilot" → Package Settings →
  "Change package visibility" → Public → type "pilot" to confirm.

This only needs to be done once.
