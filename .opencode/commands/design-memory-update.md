Update the project UI design memory based on the completed or proposed UI work.
User request or context:
$ARGUMENTS
Use this workflow:
1. Identify the UI work or design decision being summarized.
2. Inspect `docs/ui-design-memory.md` if available.
3. Separate known facts from assumptions.
4. Identify what should become durable project memory.
5. Do not rewrite the whole memory file unless explicitly requested.
6. Propose a focused patch grouped by section.
7. Ask for approval before editing the memory file.
8. Do not add vague taste statements. Make each rule actionable.
Evaluate whether the work introduced or clarified:
- Product identity
- Brand tone
- Visual personality
- PWA experience principle
- Design-system rule
- Approved visual pattern
- Approved component decision
- Motion/interaction rule
- Conversion/UX rule
- Accessibility commitment
- Anti-pattern to avoid
- Open question
- Change-log entry
