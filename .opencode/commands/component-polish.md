Use this workflow:
1. Identify the component, variant, and usage context.
2. Separate known facts from assumptions.
3. Inspect relevant component, style, token, theme, and nearby usage files only.
4. Identify the component’s role:
   - primary action
   - secondary action
   - card
   - form input
   - nav item
   - modal/dialog
   - list item
   - status/state display
   - other
5. Review:
   - hierarchy
   - spacing
   - typography
   - color/surface treatment
   - radius/border/shadow consistency
   - hover/focus/active/pressed states
   - disabled/loading/error/selected states
   - mobile/touch behavior
   - accessibility
   - motion/interaction polish
6. Use relevant skills on demand:
   - design-system-polish
   - motion-interaction-polish
   - accessibility-performance-check
   - mobile-touch-ergonomics when relevant
7. Ask before editing unless the user already approved implementation.
8. Avoid dependency additions.
9. Avoid broad rewrites.
