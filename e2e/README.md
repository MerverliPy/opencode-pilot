# Pilot E2E Tests

Playwright end-to-end tests for the Pilot PWA. Covers UI rendering, accessibility, visual regression, performance, terminal WebSocket, and full-stack flows.

## Quickstart

```bash
npm install
npx playwright install chromium
npm run test:e2e
```

New to E2E tests? Start with the [Quick Guide](docs/quick-guide.md).

---

## Test structure

Tests organized by journey in subdirectories under `tests/`:

| Directory       | Spec files                                    | What it validates                                     |
|-----------------|-----------------------------------------------|-------------------------------------------------------|
| `navigation/`   | `routes.spec.ts`                              | Route rendering, internal links, multi-page lifecycle |
| `chat/`         | `interaction.spec.ts`, `permission.spec.ts`, `sse-flow.spec.ts` | Chat UI, permission cards, SSE event flow   |
| `settings/`     | `flow.spec.ts`, `form.spec.ts`                | Server config flow, input automation                  |
| `terminal/`     | `websocket.spec.ts`                           | WebSocket terminal connection, command I/O            |
| `visual/`       | `screenshot.spec.ts`, `regression.spec.ts`    | Screenshot baselines, pixel-level visual regression   |
| `viewport/`     | `emulation.spec.ts`, `responsive.spec.ts`     | Mobile/tablet/desktop viewports, safe-area, resize    |
| `diagnostics/`  | `console.spec.ts`, `network.spec.ts` | Console errors, network requests |
| `diagnostics/`  | `performance.spec.ts`, `performance-regression.spec.ts` | CDP metrics, perf budgets |
| `accessibility/`| `wcag.spec.ts`                                | WCAG 2.2 AA audits via @axe-core/playwright           |

## Commands

```bash
# Full suite (UI-only mode — Vite dev server auto-started)
npm run test:e2e

# Full suite (full-stack mode — Hono + Vite servers)
npm run test:e2e:fullstack

# Single test file
npm run test -w e2e -- tests/navigation/routes.spec.ts

# UI mode (headed, interactive Playwright UI)
npm run test -w e2e -- --ui

# Debug mode (inspector paused on each test)
npm run test -w e2e -- --debug

# Run tests with visible browser (headed)
npm run test -w e2e -- --headed

# Update visual snapshots (rebaseline)
npm run test -w e2e -- --update-snapshots
```

## Config

| Env var          | Default                      | Description                          |
|------------------|------------------------------|--------------------------------------|
| `E2E_BASE_URL`   | `http://localhost:5173`       | Target URL for tests                 |
| `E2E_FULL_STACK` | (unset)                      | Set to `1` to start Hono + Vite      |
| `CI`             | (unset)                      | Enables `forbidOnly`, retries (2), no auto-start |

- **UI-only mode** (default): Config auto-starts `npm run dev:ui` (Vite, port 5173). Reuses existing server.
- **Full-stack mode** (`E2E_FULL_STACK=1`): Starts both Hono server (`npx tsx server/src/cli.ts`) and Vite dev server. Reuses existing servers in dev.
- **CI mode**: `forbidOnly: true`, `retries: 2`, `workers: 1`, no auto-start web servers. Set `E2E_BASE_URL` externally.

## Screenshots & visual baselines

Route screenshots land in `tests/visual/*.spec.ts-snapshots/`. Generated by `screenshot.spec.ts` and `regression.spec.ts`. Rebaseline by deleting PNGs and re-running with `--update-snapshots`.

## Architecture

- **Page Object Model**: Page objects in `pages/` (`ChatPage`, `SettingsPage`, `TerminalPage`, `Navigation`) encapsulate selectors and actions.
- **Custom fixtures**: `fixtures/pilot.fixture.ts` extends Playwright's test with console-error capture, API-request tracking, viewport presets, and page object instances.
- **Shared utilities**: `utils/` exports centralized routes (`ROUTES`, `ALL_ROUTES`), selectors (`APP`, `SETTINGS`, `TERMINAL`, `PERMISSION`, `NAV_LINKS`), viewport presets (`VIEWPORTS`, `DEVICES`), and CSS helpers.
- **Data-testid attributes**: All stable element targeting uses `data-testid` attributes defined in selectors.

## Full-stack tests

Tests in `websocket.spec.ts`, `sse-flow.spec.ts`, and `permission.spec.ts` (full-stack section) require `E2E_FULL_STACK=1`. They auto-skip when the env var is not set:

```ts
test.skip(() => !process.env.E2E_FULL_STACK, "Requires E2E_FULL_STACK=1");
```

## Adding tests

1. Create spec in appropriate `tests/<journey>/` directory.
2. Add file-level JSDoc listing mirrored chrome-devtools-mcp tools.
3. Import custom fixtures from `../../fixtures/pilot.fixture` (or `@playwright/test` for simple tests).
4. Use page objects (`pilotPage`, `settingsPage`, `terminalPage`, `navigation`) via fixture destructuring.
5. Use `data-testid` selectors from `../../utils/selectors` and `ROUTES` from `../../utils/routes`.
6. Keep tests independent — no shared state between specs.
7. Run `npm run test:e2e` to verify no regressions.
